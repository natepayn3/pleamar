# Known limitations

Everything known to be half-done, **with its fix plan**, to be crossed off as it goes. Written down as it comes up, not at the end.

**Severity**: 🔴 blocks what comes next · 🟡 will hurt soon · ⚪ rare case. When something is fixed it moves to the table below with its date; it is not deleted.

## Cross-platform

The rule: **everything system-related lives behind `src/platform/`**, and the core only uses crates that exist on Linux, Windows and macOS. The guard is `./portable.sh`, which compiles the core against all three; today it passes.

| Piece | Linux | Windows | macOS | How it gets finished |
| --- | --- | --- | --- | --- |
| Core (model, renderer, layers, gestures, text, images) | ✅ | compiles | compiles | — |
| Windows (`platform::run_event_loop`, `PlatformWindow`) | ✅ Wayland | ⬜ says it does not know how and exits | ⬜ same | **Windows**: borderless layered window + DirectComposition for the alpha, `WM_NCHITTEST` for the input region, AppBar for `reserve`, `WM_DPICHANGED` for the scale. **macOS**: borderless `NSPanel`, floating level, non-opaque `CAMetalLayer`; transparent areas already let the click through; `reserve` does not exist and is ignored |
| Icons by name (`platform::icon`) | 🟡 naive lookup | ⬜ returns nothing | ⬜ returns nothing | Windows: `IShellItemImageFactory`. macOS: `NSWorkspace.icon(forFile:)`. Both give a bitmap, not a path: `icon` will have to be able to return pixels |
| System fonts | ✅ `fontdb` + fontconfig | untested | untested | `fontdb` reads each system's font folders; it still has to be seen running |
| Global pointer | ⬜ Wayland forbids it | easy (`GetCursorPos`) | easy (`NSEvent.mouseLocation`) | On Linux, through the compositor's IPC. It is a fact in the data graph |
| **Only compilation is checked**: nobody has run pleamar outside Linux | | | | A Windows virtual machine with a GPU, or CI that at least starts up with `wgpu`'s software adapter |

## Pending

### Services and the bar

| # | Limitation | Severity | How it gets fixed |
| --- | --- | --- | --- |
| P1 | A `path` holds **a single subpath** (one `move`) and **192 points** once flattened, curves included; and it does not know how much room it takes in a layout, so there it has to be told with `size:`. A `figure` splits an svg's subpaths into one shape each, so there the limit is per subpath and it says which layer is over it | ⚪ | Several subpaths in one `path` ask the fill to know about subpaths (the winding number would already allow it) and a cap per path instead of a global one. As for the layout: a box computed from the expressions, which today are only known once evaluated |
| P2 | No **cubic curves** written by hand (`curve a via c1, c2`), no `arc` inside a path, no choice of line caps (always round) and no miter joins, and the fill is always even-odd. An svg's cubics do come across: `figure` splits each one into two quadratics when it reads the file | ⚪ | The cubic flattens just like the quadratic; caps and joins are two more numbers in the shape; `arc` inside a path flattens into segments |
| F1 | A table can already be saved and read with JSON (see Fixed), but **that is the only format**: no TOML, no INI, which is what half a desktop's configuration uses; and a Luau table with numeric and text keys at once is saved as a map, so on the way back it is no longer the same | ⚪ | TOML would need a dependency; INI fits by hand if it is ever needed. | F2 | Watching a file **checks its timestamp four times a second**: no `inotify` on Linux, no `ReadDirectoryChangesW`, no FSEvents. The PNGs of icons that arrive as pixels are never deleted (they live in `$XDG_RUNTIME_DIR`, which is emptied at logout) | ⚪ | The position: `cursor.x`, `cursor.y` already know where the mouse is on Hyprland and pleamar-wm. ### The language

| # | Limitation | Severity | How it gets fixed |
| --- | --- | --- | --- |
| G12 | A model is **expanded in full at load time**, and its cap is 1024 records. A list of thousands already fits and can be dragged (the scene declares the window with `content:` and `for … from`, and tells the logic with `on change`), but **those four lines are written by whoever writes the scene**: the layout does not know it is virtualizing. And there is still **no identity**: if the first record is removed, the rest change content instead of moving up into place | 🟡 | `window rows` in a layout with `view:`, so it sets the `content`, the copies' offset and the notification itself. Underneath, the real thing: the renderer instantiating the body of the `for` per record —properties, zones and rules that are born and die—, with `key: r.id` |
| G18 | The compiler checks **enums** (what they are compared against, that they stay out of arithmetic), but not the other types: a yes-or-no and a number mix with no warning, which is convenient (`r.separator * 21`) and sometimes a bug. An enum is not valid as a component parameter type (it is passed as `number`). And a tree is walked with a `for` written per level: there is no component that puts itself inside itself | ⚪ | `enum` as a parameter type, with the list coming from whoever passes it; and recursive components with a cap —`Branch(c)` inside `Branch`— that the expansion cuts at the list's depth |
| G19 | Text with slots knows about live texts, decimal numbers, `upper`, `lower` and optional spans. It knows durations (`{secs, time}` → `1:07`), but **does not know** about times of day or dates (`{now, "HH:mm"}`: the bar's clock is still put there by Luau every second), thousands separators, plurals (`1 notice` / `3 notices`), or picking a text according to a condition (`{muted ? "silencio" : "…"}`). And a template is only valid as the content of a `text`: not in `placeholder:` and not as the source of an `image` | 🟡 | A time slot the renderer resolves on its own (and that wakes up once a minute, not once a second); `{n, plural: "notice", "notices"}`; and an `if(cond, "a", "b")` between texts, which is the same `if` as in expressions |
| G20 | Data goes **from the logic to the scene**, not the other way round: a rule cannot change a field (`r.checked = not r.checked`), so any change takes the long way round through Luau | ⚪ | Letting an effect write to a numeric field —underneath it is a fact, and that is already possible— and telling the logic with `model:rows` |
| G15 | The layout knows row, column and grid with gap, padding, align, anchor, `grow:` (the room that is left) and `wrap:` (see Fixed). What it still lacks: **no minimums or maximums** (a child that grows cannot say «never under 80 px»), and a `group` with no `size:` takes up whatever its last child does, by accident more than by design | ⚪ | `min:` and `max:` on a child, applied when `grow:` shares out what is left; and a group with no size taking up the union of its children |
| G17 | A text's measurement arrives one frame late, so a layout with texts settles over one or two frames at load. With a spring it is invisible; without one, a flicker | ⚪ | See T12 |
| G5 | The messages are in English now (see Fixed), but **only in English**: whoever does not read it is left exactly where whoever did not read Spanish was before. And a tokenizer error (an unclosed quote) still stops reading dead | ⚪ | Once there is someone to do it for: a key per message and a table per language, chosen by `LANG`. The work of pulling the 210 literals into one place would already be half done |
| G7 | On reload, changes to `surface` are not applied (S1), and whichever gesture was playing and the pending delays are lost | ⚪ | Reconfiguring the surface; keeping the gesture if it still exists under that name |
| G9 | The language server knows about names and about where they are used (see Fixed), but **renaming does not touch the logic**: if a `.luau` writes `fact.volume`, that stays a manual job (the compiler does warn, at least). It does not complete a record's fields (`r.label` inside a `for`), and there is no tree-sitter highlighting, so Zed and whoever only speaks that language are left without colors | ⚪ | The logic would need understanding Luau, which is another language: at most, searching for `fact.name` and `text.name` as plain text and offering that separately. A record's fields ask for knowing which model each `for` is, which the compiler already knows. The tree-sitter grammar is for another day |
| G11 | Hot reload checks the file's timestamp four times a second | ⚪ | It works on all three systems, which is why it was done this way. If it becomes a nuisance: the `notify` crate |
| G25 | The reference's **vocabulary** can no longer fall out of date (see Fixed), but **the EBNF can**: the shape of each statement —what follows what— is still hand-written text, and the only thing guarding it is the examples that get compiled. And the coverage test checks that each word *appears* in some test, not that it is used where it belongs | ⚪ | A grammar that both things come out of —the parser and the EBNF— is too much for what is here; cheaper: one minimal example per production, generated from the EBNF, that has to compile |
| G26 | The **language words are not reserved**: a fact can be called `text` or a property `for`, and whatever error comes out afterwards will not say why. And the version number **comes with no migration**: when 0.2 arrives, a 0.1 file will either be read or not, with nobody to rewrite it | ⚪ | Rejecting a declaration whose name is a language word, with the list in plain sight. And `pleamar --migrate file.plm` once there is a first breaking change: while the first number is 0, what changed is written down in note 11 |
| G22 | A plugin **has no surface of its own**: it lives inside the scene that imports it. If something needs its own, it is a scene; and two scenes share no state: one tells another `--say`'s commands (`sys.call("say", …)`), unchecked by the compiler at either end | ⚪ | Several scenes running in the same process (S2 asks for this too) and talking to each other through events named by scene, which the compiler checks at both ends (issue 75, B); then a `shared fact` with an owner (C) |
| G24 | Libraries are looked up **only next to whoever imports them**. There is no system folder and no user folder (`~/.local/share/pleamar/lib`), and no versions | ⚪ | A list of folders to search, behind `platform/` (on each system they are somewhere different), and `import "pleamar/menu"` with no extension for the installed ones |

### Text and images

| # | Limitation | Severity | How it gets fixed |
| --- | --- | --- | --- |
| T12 | A text that appears **for the first time** is not visible until the workshop delivers it (one or two frames); one that *changes* shows the previous one meanwhile. And a text's measurement reaches the expressions one frame later | ⚪ | Whatever is already in the scene when it loads is asked for before the window exists. For the rest: composing twice on the frame where a measurement changes |
| T3 | A single RGBA atlas, 2048 wide: 16 MB of VRAM even when it is nearly empty. On exhaustion, the workshop rebuilds current text and live images plus declared scene images, reclaiming old entries; if what is seen still does not fit, it grows to 2048 × 4096 and then 2048 × 8192 (64 MB), and does not shrink again while the program runs. A working set beyond that is reported. A still picture over 2046 real pixels on a side, or a live one over a quarter of the atlas, is a texture of its own (below); an animation that big is still made smaller, the same shape, and shown a little softer | 🟡 | Starting at 512² and growing; glyph masks in a single-channel atlas; shrinking again when a scene that needed it is gone |
| T4 | Glyphs are rasterized at the scale of the **sharpest** render surface; the others see them scaled down. With one monitor at 2 and another at 1, on the one at 1 the text comes out a touch soft | ⚪ | One atlas per scale, and each render surface having its own `uv`: that asks for a table of elements per render surface instead of a shared one |
| T5 | Text under a transform that scales is resampled (scaled up, it comes out soft), and rotated it does not land on whole pixels | ⚪ | Rasterizing at the transform's `scale × factor` once it has been still for a few frames |
| T6 | No rich text (bold or a color mid-paragraph), no letter spacing, no underline, no selection and no editing | 🟡 | `cosmic-text` already has spans with attributes: exposing `Content::Rich`. Editing is another project (IME included) |
| T7 | When lines are broken, a space is left at the start of the new line | ⚪ | Looking at how `cosmic-text` treats the trailing space with `Wrap::WordOrGlyph`; if there is no setting for it, trimming it when placing the glyphs |
| T8 | A template is assembled **on every frame** that gets painted, even when nothing has changed: a new string per text with slots. Not noticeable with dozens; with hundreds, yes | ⚪ | Keeping the assembled string next to what its parts were worth, and redoing it only if one of them changed |
| T9 | Images have a maximum size declared by the scene. No URL, no GIF, no nine-patch. When the scale changes they are all re-rasterized | 🟡 | A disk cache of the already-rasterized SVGs; size taken from the destination instead of declared |
| T10 | Icon lookup does not read the `index.theme` files and does not know which theme is in use: it tries the usual ones and takes the first one | 🟡 | The real freedesktop lookup (current theme, inheritance, sizes). It lives in `platform/` |
| T11 | Linear gradient only; no radial, no blur, no masks | 🟡 | The radial is ten lines of shader. Blur asks for another pass per layer: the opacity-layer infrastructure already works for it |
| T13 | **Atlas reclamation rebuilds the current working set.** Old live images are evicted when allocation fails; the render keeps its previous frame until replacement layouts and uploads arrive together. Decoding current images again can delay their replacement on the workshop thread | 🟡 | Incremental shelf eviction or additional atlas pages to avoid rebuilding all current resources |
| T14 | A live image that is not found paints nothing: there is no fallback image. (And many are not found because of T10: here, Avahi's two) | ⚪ | `fallback: icon "application-x-executable"` on the `image`; and fixing T10 |
| T15 | **The lens needs `wlr-screencopy`, and to know where the surface is.** It works out what is behind the glass from a screenshot of it, so it needs a compositor that gives one (Hyprland, Sway, river…). Where each surface is on its monitor is asked of Hyprland (at most once a second: a window moves without being reconfigured); on another compositor a layer is worked out from its anchor and margins —wrong if another bar pushes it aside— and a normal window has no lens. On Windows and macOS the glass is a tint with its light and nothing behind. The lens costs ~1 point of a core in pleamar and 2 or 3 in Hyprland while something moves (a screenshot at most every 50 ms, or what the scene says with `lens every`; `lens hold while` stops them), nothing when still, and ~6 MB of video memory for a 720 × 320 surface. Hyprland lowers the opacity of normal windows (`decoration:active_opacity`), and that is accounted for; an opacity set by a window rule is not, and the background comes out slightly off. Under text and icons (fully opaque) the background cannot be worked out: it is filled in from around | 🟡 | Windows 11: `WDA_EXCLUDEFROMCAPTURE` on the window and a capture of the desktop behind it gives the real background, no working out needed. macOS 26: the system's own glass (`NSGlassEffectView`). Both behind `platform::PlatformWindow`. Other compositors: asking them where each surface is, if they ever say |
| T16 | **Seen once, not reproduced: a text inside a `row` of a library component showed the other language** (Calima's chip said «Remoto» with `LANG=en_US`, 2026-10-26). The same scene at the same commit, run again, and minimal scenes (a row in a library component, in a named `screens: each` surface, with and without `lines:`/`weight:`) all showed the right language. Maybe a race between the row measuring its texts on the first frame and `locale` being set from the system | ⚪ | If it shows again: log the `locale` fact and the row's measured texts on the first frames; a test scene that starts with a non-default `LANG` and reads the row's width |

### Painting

| # | Limitation | Severity | How it gets fixed |
| --- | --- | --- | --- |
| P4 | A group with opacity inside another one gets no layer of its own: it multiplies —and one with only opacity around a group with effects gives its layer up to it—. Two groups with effects cannot nest (it is an error). There is no limit of four any more: they share up to four layers —those that do not reach each other go on the same one, painted in one pass—, painted in turn | ⚪ | Painting the inner ones before the outer ones, into a stack of layers |
| P5 | With a different scale on each axis, the edge antialiasing is approximate | ⚪ | Measuring the distance gradient in the shader (`fwidth`) instead of a fixed factor |
| P6 | The gradient and the light live in the group's space: if the shape rotates *by itself* (`.rotated`) they do not rotate with it | ⚪ | Evaluating the paint in the space of the body's first shape |
| P7 | **Every glyph is an element**: a paragraph is hundreds. There is no cap any more (the stores grow), but it is extra work for the graphics card | ⚪ | One element per *line* of text, walking its glyphs in the shader. And the nested clips that clip by their shape are still four: the outermost ones clip by their box (it warns once) |
| P11 | **Presenting a frame costs ~0.5 ms of CPU no matter what**, whatever it draws: 0.10 ms to record the commands, 0.20 to close the encoder and 0.20 to submit it and present. That is wgpu's floor on top of Vulkan, and it is what makes animating at 60 Hz cost ~4.3% of a core even when all that moves is a circle (measured with `PLEAMAR_TIMING=1`, which prints the breakdown). The vsync wait is 16 ms of sleep, not of CPU | 🟡 | A single `submit` for all the frame's render surfaces instead of one per render surface; reusing the `CommandEncoder` when wgpu allows it; and looking at whether a precooked `RenderBundle` saves the `finish`. For reference: Quickshell doing the same spends 11.9% |
| P9 | The first frames after waking do not wait for the screen: the animation clock runs on CPU time, not on presentation time | 🟡 | `wp_presentation` on Wayland (and its equivalents) to know when each frame was shown, and advancing the springs with that time |
| P10 | One frame in ~400 drops to 33 ms. Not investigated | 🟡 | Measuring with GPU timestamps to find out whether it is pleamar's or the compositor's |

### Surfaces and input

| # | Limitation | Severity | How it gets fixed |
| --- | --- | --- | --- |
| E1 | **Wheel, buttons, drag, hold, keys and cursor are tested with the fake script**, which comes in through the renderer. The Wayland side —that the notches arrive with their sign, that the cursor changes, that the keyboard arrives with `on_demand`— nobody has seen with a real mouse | 🟡 | Abel trying it on the bar: the wheel over the volume, dragging the little bar, the speaker, and the pointing hand over the workspaces |
| E4 | The wheel adds the vertical and the horizontal together, and a touchpad is turned into notches by eye (15 px per notch). Dragging a list works now, but **with no inertia**: on release it stops dead, it does not keep gliding | ⚪ | `wheel.x` and `wheel.y` separately, and continuous scrolling in pixels. Inertia is an impulse to the scroll spring with the speed of the last few millimetres, which the renderer already knows how to measure (`vel`) |
| E5 | The right button closes a panel scene that does not use it | ⚪ | It is the prototype's emergency exit, for a panel with no keyboard and no frame. Never for a scene that uses `on press right`, nor for a `kind: window` (its frame has a close button) or a `kind: lock`. It will go once there is a command to close |
| E6 | A zone being dragged inside an anchored layout moves under the mouse if the layout changes size. Today it is avoided by hand, giving a fixed width to whatever changes | ⚪ | `min_width:` on the children, or freezing the layout while a drag lasts |
| E7 | **No IME**: Japanese cannot be typed in the input field and there is no composing with an input method. Dead keys (´ + a) do work, since xkb resolves them | 🟡 | `zwp_text_input_v3` on Wayland, TSF on Windows, `NSTextInputClient` on macOS, all three behind one `platform::Ime` that hands the renderer "text being composed" and "committed text" |
| E8 | **The input field, the focus and the drop are tested with the fake script**, which comes in through the renderer. Nobody has seen them with a real keyboard: `keyboard: exclusive while open` (left untested so as not to take Abel's keyboard away mid-task), `on blur` arriving on a click outside with `on_demand`, or a real drag from Dolphin | 🟡 | Abel trying it with the launcher: opening it with the bind, typing, Escape; and dropping a file onto a test scene. **Careful: with `exclusive` the compositor does not release the focus on a click outside**, so `on blur` does not close there — it would need `hyprland-focus-grab` or a full-screen zone |
| E9 | The input field is **single-line**, with no undo (Ctrl+Z), no double click to pick a word, and no password field | ⚪ | `lines:` on `input` with the same `Layout.cursors` (it already gives each letter's line); a stack of states in `Editing`; `mask: "•"` |
| E10 | A drag can be **received**, but not started towards another application. And only `text/uri-list` and `text/plain` are accepted | ⚪ | `wl_data_source` when dragging a zone with `drag: text`; on Windows and macOS, their `IDropSource` and `NSDraggingSource` behind `platform/` |
| E11 | **The global shortcut depends on the compositor**: it is a bind of its own that launches `pleamar --say`. And the commands from outside are a Unix socket: on Windows `--say` does not exist yet | 🟡 | A named pipe on Windows (`\\.\pipe\pleamar-SCENE`) behind the same function. For the shortcuts: `RegisterHotKey` on Windows, `CGEventTap` on macOS, the `GlobalShortcuts` portal on Linux; with a `shortcut: Super+space` in the scene that for now only warns that the bind is needed |
| P13 | Frames are paced by the renderer's own clock at the monitor's period, not locked to its vblank (see P12 in Fixed): over a long animation the two can drift by a frame, which would show as one repeated frame now and then. Not seen so far. The compositor's frame callbacks are now requested (see Fixed), but **they cannot be the metronome on Hyprland**: it answers when it composes, and a frame that lands just after it composed makes it compose again and answer at once — two frames per refresh, one of them thrown away. They are used to know whether the surface is being shown | ⚪ | `wp_presentation`, which says when a frame *was shown*, not when the compositor would like another: pacing on its timestamps instead of a timer, behind `platform/` |
| S1 | A surface's size is declared by the scene and is fixed: **it does not grow with what it holds**. A card with `shadow: 0, 18, 44` needs 62 px of room below it, and without them the shadow stops dead against the edge. This much is not pleamar's alone —a layer-shell surface asks for its size on both sides, and Marea raised its own ceiling by hand three times, 520 → 640 → 880, with a note in `core/Theme.qml` saying the symptom pointed nowhere near here— but that does not make it right. What **was** pleamar's own fault is that nothing said anything, in a runtime whose whole promise is that mistakes are caught: since 2026-09-20 the renderer says it (see Fixed). Saying it is not growing it. And on hot reload the surface is not reconfigured (it has to be relaunched) | 🟡 | The scene being able to change its `Surface` and the platform reconfiguring it. Growing on its own is a separate question and probably a bad idea while something is animating: a surface that resizes every frame is a surface that flickers.
